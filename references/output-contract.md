# Output Contract ——「我用 Agent 干了啥」报告契约

## 设计原则

- 交付物是**单个自包含 HTML 文件**（瑞士国际主义风格），双击即开、离线可读、可直接转发。
- 报告只陈述本机可见记录能支持的事实，语气轻松但不夸大；不含任何打分、排名、评审或考核内容。
- 不要求用户补充材料：没有记录的内容就不写，或标"未记录"。
- 机器产物（JSON）不进交付目录，留在会话工作区 `<work>/`。

## 输出位置与命名

**始终输出到桌面**：`~/Desktop/`（Windows：`%USERPROFILE%\Desktop\`）。

文件夹名：`{署名}_{期间标签}_我用Agent干了啥/`，内部只有一个与文件夹同名的 HTML 文件：`{署名}_{期间标签}_我用Agent干了啥.html`。

文件名必须与文件夹同名（而不是 `index.html`），保证用户单独转发这个文件时，接收方能直接看出是谁、哪个时期的报告。

期间标签自动推导：

- 起止正好等于自然季度（1-3 月=Q1，4-6 月=Q2，7-9 月=Q3，10-12 月=Q4）→ `YYYYQn`（如 `2026Q2`）
- 否则 → `YYYYMM-YYYYMM`（如 `202604-202606`）

示例：`~/Desktop/小朱_2026Q2_我用Agent干了啥/小朱_2026Q2_我用Agent干了啥.html`

目录已存在时追加 `_v2`、`_v3`（文件夹与内部文件名同步加后缀），不覆盖。

## 数据管线（两个脚本）

```text
Agent 盘点整理 → report_input.json（<work>/）
   ↓ build_report_data.py（校验 + 确定性统计）
report_data.json（<work>/）
   ↓ render_report.py（纯模板渲染）
~/Desktop/…/{署名}_{期间标签}_我用Agent干了啥.html
```

## report_input.json schema

Agent 在深挖阶段结束后组装此文件。必填：`owner`、`period_start`、`period_end`。

```json
{
  "owner": "小朱",
  "period_start": "2026-04-01",
  "period_end": "2026-06-30",
  "agents": [
    {
      "name": "Proma",
      "emoji": "⚡",
      "session_count": 198,
      "first_seen": "2026-04-02",
      "last_seen": "2026-06-29",
      "note": "代码实现 / 文档整理 / 调试"
    }
  ],
  "projects": [
    {
      "name": "周报自动化",
      "one_liner": "用 Agent 把每周数据汇总从 2 小时压到 10 分钟。",
      "ai_tools": ["Proma"],
      "activity": "2026.04 – 2026.06",
      "badges": [{"text": "效率成就 · 省时 90%", "level": ""}],
      "milestones": [{"date": "2026-05-11", "text": "第一版脚本上线"}]
    }
  ],
  "narrative": {
    "headline": "把重复劳动交给 Agent，把判断留给自己。",
    "paragraphs": ["……轻松的第一人称短文，2-4 段……"]
  },
  "session_timestamps": ["2026-04-12T23:40:00", "2026-04-13T09:10:00"]
}
```

字段说明：

- `agents[]`：`name` 必填；`session_count` 为该 Agent 在时间段内的会话数（拿不到就省略，不编造）；`first_seen/last_seen` 为活跃区间；`note` 一句话分工。`emoji` 可省略（脚本有内置映射）。
- `projects[]`：只放"你做的"项目（下载的开源项目不进）。`badges[].level` 可选 `""`/`rare`/`epic`（仅影响配色，不代表等级评价）。
- `narrative`：Agent 代写的轻松总结，用户可改。**没有固定模板**：`headline` 可省略，`paragraphs` 段落数不限（建议 2–4 段），结构、切入角度、详略都由 Agent 按 `references/narrative-writing-guide.md` 的风格原则自由发挥——指南里的范文是灵感参照，不是填空模板。报告版块标题里的周期词（「本月总结」「本季总结」「今年总结」「这段时间的总结」）由脚本按实际复盘周期自动生成（`meta.period_noun`），文案里提到周期时与 `period_noun` 保持同一个词。**风格底线是确定性的**：`build_report_data.py` 会扫描 narrative 和 `agents[].note` 里的 AI 腔禁用词（协助/赋能/闭环/成功完成……），命中写入输出的 `style_warnings` 并在终端警告；有警告必须重写后重跑，不带警告才能交付。
- `session_timestamps`：可选。会话时间戳列表（来自文件 mtime 或会话元数据，**不读内容**即可获得）。提供后脚本确定性计算隐藏战绩。

## 校验规则（build_report_data.py 强制）

- 缺必填字段、日期格式错误、`period_end < period_start`、`session_count` 为负 → 报错退出，不生成半成品。
- milestone 日期必须可解析；时间线由所有项目里程碑自动合并排序。
- 趣味统计口径固定：夜猫子=23:00–05:00；早起鸟=05:00–07:00；周末=周六日；火力全开月=会话最多的月；连续并肩=连续有会话的最长天数；单日爆发=单日会话峰值；固定搭子=会话最多的小时段；最晚/最早收开工=按跨夜换算的时刻记录；神隐=相邻活跃日最大间隔。
- 呈现规则：记录类 tag（火力全开月、最晚收工）无阈值；计数类用宽松阈值（夜猫子/早起鸟 ≥2、周末 ≥1、连续并肩 ≥2 天、单日爆发 ≥3 次、固定搭子 ≥3 且 ≥15%、神隐 ≥7 天、月度全勤=周期≥2 个月且月月有会话）；最早开工仅在 08:00 前呈现。

## 渲染规则（render_report.py）

- 单文件、无外部资源（字体走系统栈）、无 JS、无网络请求。
- 所有用户/数据文本一律 HTML 转义。
- 空区块自动省略（例如没给 timestamps 就不显示"隐藏战绩"）。
- 页脚固定包含：生成时间、skill 版本、"仅供个人回顾与分享娱乐，不代表任何第三方评价"声明。

## 不做的事

- 不生成任何提交包/正式包，不收集工号等身份信息。
- 不要求用户补充材料；没有记录就不写或标"未记录"。
- 不复制任何源文件；报告不引用本地绝对路径（避免转发时泄露目录结构），只写项目名与一句话描述。
- 不加水印、不做哈希校验、不做 zip 打包。
- 全文不出现打分、排名、考核、合格等评价性字眼。
